# M128 — CI: the same acceptance run, locally and on a runner

`tools/acceptance.py` (M126) gave one verdict; the pre-commit hook (M127) enforced it before a commit. This adds
the third place it has to hold — a clean checkout — and makes the suite honest about what a checkout *cannot*
contain.

## `tools/ci.sh`

Three checks, ordered so the most informative fails first:

```
$ sh tools/ci.sh
== fixtures                    all 5 runnable suite(s) pass (48 cases)
== tracked artefacts           none (ok)
== cartridge integrity         PASS sha256 71f3f779…   expected 71f3f779… (build/elfs/images.json)
ci: ok
```

* **fixtures** — delegates to `tools/acceptance.py`, the same suite the hook runs, so there is one definition of
  "green";
* **tracked artefacts** — fails if `rom/`, `assets/`, `build/` or any `.z64/.n64/.bin/.elf` is tracked. That rule
  has been in the notes since M1 and was never machine-checked;
* **cartridge integrity** — the cartridge must still hash to the value in `build/elfs/images.json`. This is the
  "print the sha256 before and after" rule, automated.

## The design decision that makes CI possible at all

The cartridge is **gitignored by design**, so no runner can have it, and `build/` is gitignored too. Two suites
therefore cannot run in CI: the corpus provenance fixpoint and the two pre-registered acceptance tests over the
real images.

They report **SKIP with the reason**, not PASS:

```
cartridge: ABSENT — suites that need it will report SKIP
provenance acceptance     -          SKIP (needs the cartridge)
```

That distinction is the whole point. A suite that cannot run and reports success is the same class of error as a
fixture that asserts nothing: the number looks green and means nothing. So CI covers **45 of 48 cases** — every
synthetic fixture — and the three corpus checks stay locally enforced, by the hook and by `ci.sh` where the ROM
exists.

`ci.sh` also needs `build/elfs/images.json` for the integrity check, which a fresh clone also lacks; that path
reports SKIP with its own reason rather than throwing.

## `.github/workflows/acceptance.yml`

The same run on a runner: checkout, python, `sh tools/ci.sh`, preceded by a step that prints whether the ROM is
visible so the log states its own limits.

**It is dormant.** This repository has no remote (`git remote -v` is empty), so nothing triggers it yet. It is
committed because the moment a remote exists the suite should run there without anyone remembering to add it —
and because writing it down forced the SKIP semantics above, which improved the local behaviour too.

## Verification

* locally: `sh tools/ci.sh` → 48 cases, no artefacts, sha256 PASS.
* on a **clean clone** (`git clone` to a scratch directory, no ROM, no `build/`): every ROM-free suite passes, the
  corpus suite reports `SKIP (needs the cartridge)`, the integrity check reports its own SKIP, and the script exits
  0 — i.e. a runner gets a truthful green, not a vacuous one.
