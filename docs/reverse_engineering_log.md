## The errors worth remembering

1. **A guessed example poisoned fifteen files (M7).** `tools/wrap_mips_elf.py`'s usage line said `--base 0x80000000`, so every hand-computed vram address was `0x480` low. It survived five milestones because the wrong addresses still pointed at real code. *Check the base before using any address, and prove it numerically.*

2. **The `jal` sweep needed the 26-bit mask and the real function start.** Sweeping for the encoding of an interior address reports "no callers" no matter how many exist — that produced a nonexistent cross-bank foothold and a whole arc of dead ends.

3. **Three null results were filter artefacts.** `offset < 0x4000000` (the real offsets carry a `0xB` flag), adjacent `(rom, vram)` pairs (the record is `offset, size, vram, vram_end`), and `CMF == 0x78` (these streams use `0x68`). Each time the data was present and the search constant was invented.

4. **A constant's *mode* is part of the constant (M84).** `lui 0x800c` + `addiu v0,v0,-23464` is `0x800c0000 - 0x5ba8 = 0x800ba458`; the scanner beside the disassembler composed it with `ori` semantics and got `0x800ca458`. The wrong address was *plausible* — it pointed at the same .rodata bank — so the tables looked empty and a runtime writer was hunted for two sessions. The disassembler printed `-23464` on the same line as the bug: **when two tools disagree, check which one is being consumed, not which one looks trustworthy.**

5. **A hand-composed address is where every remaining error lives (M84/M86/M87 — four instances).** `ori` for `addiu` gave `0x800ca458` for `0x800ba458`; `+ 0xb264` for a sign-extended `lw` gave `0x800fb264` for `0x800eb264`; a 28-payload span was quoted as 81 852 instead of 74 716; and `0x80004550` was read out of the stage-2 image when it lives in the boot bank. **The fix is `tools/vaddr.py`, not discipline**: `sext16`/`compose(hi, imm, mode)` with no default mode, and `locate()` refusing when several images share the address.

6. **A register name is not a register value.** Grepping `sw …,4(v1)` gave 105 apparent PI writes; a small data-flow window that aborts on redefinition gave the true 2.

7. **An analysis rule under-invalidates as easily as it under-matches (M95).** Constant tracking that skips **loads** leaves stale values alive: `t4` kept `0x80113a34` across `lw`s and every access through it was reported as if it hit that address — 167 false near-misses around a table whose real reader sat one line away. The scan's *rule*, not just its arithmetic, decides what can be seen.

8. **A near-miss list is a candidate list, not evidence (M95/M99, three instances).** `find_readers`' base+register hits were taken as attributions twice — `0x80113a34` in M93 and `0x80171e80` in M98 — and both fell apart on reading the site (a loaded-over register; gameplay float code). The rule: a scanner output becomes a fact only after the instruction at that PC is read.

9. **Never convert an address in your head (sixth instance, M94).** Locating a pointer table I read `2148612520` as `0x80113a68`; it is `0x801139a8`, off by `0xC0`. The wrong address produced a table of *different* real function pointers — plausible, and therefore dangerous. `python3 tools/vaddr.py <addr>` and `tools/find_readers.py` answer the question without arithmetic; the mitigation for this class is asking them, not being careful.

10. **A file only a remote service parses is unverified (M174).** `.github/workflows/acceptance.yml` was committed in M128, rewritten in M130, and **never ran once**: an unquoted `: ` inside a plain scalar made it invalid YAML, so GitHub rejected it at load and nothing in the repo could notice — the file that makes CI run is the one file CI cannot test. Two milestones of prose about "51 of 54 cases" were describing scheduled work that did not exist. *Parse the artefact locally, and give it a gate that needs no remote.*

11. **`ls` hides the directory you are looking for (M174).** Asked to add a CI workflow, I wrote a second one: `.github` is a dotfile directory, so a plain `ls` of the root did not show it and I never checked. The answer was in the repo the whole time. *Ask git (`git ls-files .github`), not your eyes.*



## Working method that produced the answer

- **Change an execution model only under a fixture, and encode the *architecture*, not the current
  output (M87).** The harness passed for a year against a countdown loop that touched `addiu`,
  `addu`, `bnez` and `jr` — none of `LB`, `LH`, `SWL`, `SWR`. "Verified path" was true of the whole
  and false of the parts. Write the failing table first (5/15), fix, then require both the new table
  and the old smoke test to pass (15/15). The same form was used for CP0, which is why CP0 stayed
  fixed.
- **Read the cheap artefact first**: `rea decompile … --format json` puts pseudocode in
  `normalized_result` as a plain string; `rea instructions` returns a bounded array. Reserve
  `detail:"complete"` for fixtures.
- **A dispatcher states its own table length (M84).** `sltiu v0,v1,K` immediately before a
  `lw`/`jr` dispatch bounds the jump table at `K` entries. Checking `entries_found == K` is a
  falsifiable test, not an inspection: it caught a walk that read 27 entries where the table had 12,
  because it ran on through the padding into the next table. Assumption to state: a table with a
  default case has `K + 1` entries and will trip this test.
- **Prefer derivations over inspections**: 1 226 known frame transitions score a length field better
  than any amount of staring at a hexdump, and the score is falsifiable.
- **Self-consistency is not truth**: the trailer rule is only believed because an independent
  consumer (`ffprobe`) accepts the concatenated output.
- **Keep discovery and extraction separate** (`scan_headers.py` vs `extract_blocks.py`), so a wrong
  hypothesis cannot quietly produce wrong output files.
