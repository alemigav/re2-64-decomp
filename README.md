# Resident Evil 2 (N64) — decompilation research

**What it is:** a black-box study of *Resident Evil 2* on the Nintendo 64 (`NREE` rev 1 USA), reverse-engineered from the
cartridge up — 3 664 functions catalogued, the file formats decoded, the script virtual machine and three audio codecs
worked out from the bytes, and **274 functions reconstructed in C and recompiled — 273 of them matching the game's own
machine code byte for byte**. It ships a **1384-case verification suite**, and every claim here is either measured by
one of those cases or explicitly labelled a reading of the code.

> **Two versions of this page.** This is the short one: what the project is, what it proves, how to check it in a
> minute, and where the work stands. The **dense technical companion —
> [docs/README-extended.md](docs/README-extended.md)** — carries the toolchain profile, every recovered function, the
> format reference, the verification architecture and the residue list. A cold session that wants to *continue* the
> work starts at [docs/handover.md](docs/handover.md).

## The result, in one table

| | |
|---|---|
| **The result** | The compiler that built this game is **identified and reproduced** — gcc 2.8.1 for MIPS-ELF — and **273 functions match the cartridge exactly**, to the last byte, out of **274 reconstructed in C**: from Nintendo's own libultra runtime down to single-instruction accessors. 97 of them are copies of 21 proven body shapes, so one proven shape registers every copy; an earlier arc re-verified 194 more from another decompilation, and those are **gone** — removed in M369 for want of a licence ([the corpus, honestly counted](#the-corpus-and-what-is-left)) |
| **The unusual part** | **357 checks run with no ROM, no assets and no emulator** — the other 1027 need your dump and say `SKIP`, never `PASS` — plus a verifier that refuses `PASS` unless it has first proved each gate *can* fail |
| **The scale of what is left** | 63.3 % of the image bytes sit inside a known function body and the rest is classified rather than guessed; finishing 64 MB is a community-scale effort, so every stage ships as it lands |

**This is not a matching build** — of the whole cartridge, and there is **no Makefile, linker script or ROM
target**: `src/` cannot be compiled as it stands, because what compiles here is **one function at a time**, through
`tools/compile_probe.py`, at the address the cartridge puts it. But that is no longer the only thing the project can say
about the matching question: the compiler that produced this game is identified and reproduced, whole functions are
reconstructed from the image and recompiled **to the byte**, and the *first named function* (`main`) and the *first
library function* (`osCreateMesgQueue`) are both in that set.

## Proof, in bytes

One of the 15: `osCreateMesgQueue`, nine instructions of Nintendo's runtime, at `0x80006d30`. Here is what the cartridge
holds and what this repository's C compiles to — same nine words, 36 of 36 bytes:

```
cartridge   3c028001 24422940 ac820000 ac820004 ac800008 ac80000c ac860010 03e00008 ac850014
this repo   3c028001 24422940 ac820000 ac820004 ac800008 ac80000c ac860010 03e00008 ac850014
            ^ lui v0,0x8001 / addiu v0,v0,0x2940 (&__osThreadTail) ... jr ra / sw a1,0x14(a0) in the delay slot
```

A case in the suite compiles that C and asserts the 36 bytes. The one recovered function that does not yet match is
published as **226 of 229 words** rather than rounded up, and the largest function attempted —
`vector_installer`, 132 words — is published as a measured near-miss whose every region is within one word
([its ledger](docs/README-extended.md#3a-vector_installer--a-measured-near-miss-with-its-ledger)).

## Quick start — 60 seconds, no cartridge

```sh
git clone https://github.com/alemigav/re2-64-decomp
cd re2-64-decomp
python3 tools/verify.py     # -> PASS-FAST: 357 cases run, 1027 SKIP (they need your dump, never PASS)
```

That is the whole setup: Python 3, no dependencies, no cartridge. `python3 tools/acceptance.py` lists the suites by
name; `python3 tools/verify.py --full` adds the mutation audit, which re-runs every gate with its mechanism disabled and
requires it to fail. With a dump of your own, see [Rebuild with your own dump](#rebuild-with-your-own-dump).

## Build it

The corpus is not only measured, it **builds**: `make` compiles every reconstructed function with the canonical profile,
links each at the address the cartridge puts it, and stitches the results into an image-shaped binary per image.

```sh
make            # -> build/corpus/<image>.elf and <image>.bin, one pair per image, plus index.json
make check      # the same, then compares every function against the cartridge: 273 exact, 1 differs
make test       # the fast gate the acceptance suite runs
```

That comparison is a **verdict**: `make check` exits non-zero only if a body the fixture calls byte-exact fails to
match, so a published partial is allowed to differ and a regression is not. The single function that differs is
`0x8007e590` at its published **226 of 229** — the twelve that used to differ did so because their **constant pool** (a
jump table) needs the image's own address for `.rodata`, and that address is no longer per-function knowledge to type
in: `manifests/jump_tables.json` already records every dispatcher and its table, and the build derives the pool address
by containment in the function's extent (M374), cross-checked against the twelve addresses the probe places by hand.
**This is still not a ROM** — data and unrecovered code are holes, and each image reports the share it
covers — but it is the first artefact here that a downstream tool could open, and the shape a static recompiler wants
(an address-bearing image).

## Verify it without the cartridge

```sh
python3 tools/acceptance.py      # 37 suites / 357 of 1384 cases run; the other 45 suites SKIP
python3 tools/audit_gates.py     # 160/160 — every gate must fail when its mechanism is disabled
python3 tools/workflow_lint.py   # 14/14 — CI lints the file that makes CI run
python3 tools/check_markers.py   # 25/25 — every doc anchor, heading and note pointer holds
python3 tools/artefact_scan.py   # 5/5  — no tracked file is cartridge content
python3 tools/ratchet.py --check # the registry has not drifted, and src/ has not moved, silently
python3 tools/counts.py --check  # every number quoted on this page still agrees with the registry
python3 tools/verify.py          # all of the above, adjudicated into one verdict
```

A suite that cannot run prints `SKIP (needs the cartridge)` — **never PASS** — and the split is stated wherever it is
counted: **1027 of 1384 cases cannot run without your dump**, and the CI job summary lists them by name. The mutation
audit is the unusual one: it **disables each check's mechanism** and requires the check to fail, 160 mechanisms and 160
failures with **0 vacuous**, after first running the unmutated tool as a positive control — that control once found that
49 of 132 audits had never tested their mutation. [The extended page](docs/README-extended.md#6-the-verification-architecture)
has the architecture, the ratchet's three invariants and the 30-second rule.

one written from measurement, and that distinction is the project's whole claim.

## The corpus, and what is left

- **The code corpus**: **36 images** (boot + stage-2 + 34 overlays, 1 956 560 B) censused from the cart's own load
  table — **3 664 functions** over **3 678** ranges, **63.3 %** of the **1 956 560** image bytes inside a known body
  (**1 238 404 B**); `src/`, `src/INDEX.md`. The other 36.8 % is classified, not shrugged at: **408 124 B padding**,
  **6 680 B** data the decompiler names, **980 B** of jump tables, and **440 B (0.0 %) unclassified** — a bucket
  that is published and never renamed `data` on a hunch.
- **What is actually understood**: of **3 664 functions**, **3 408** resolve every call target in their bodies, **33**
  carry a curated name, and **12** have behaviour pinned by a gate or an executed experiment — and all **12** of those
  are still called `FUN_…`, because a name needs evidence of its own.
- **The recovered corpus is 274 entries, 273 byte-exact** — and the count needs its qualifier, which is now derived
  rather than typed: **97** are copies of **21** proven body shapes — 44 the empty function, **17 the dispatch family**
  across eight table addresses, 11 a masked call wrapper, and the rest two- and three-copy shapes closed by statement
  order, by a strided index, or by where a constant sits in an OR chain. The other **177** are not copies: **52** landed
  from the screening tool, **106** read by hand from the disassembly, **19** one-off probes. All of those figures are
  derived from the corpus and asserted by `tools/counts.py` — the check that was missing while this sentence claimed
  46 + 55 against a corpus of 210. An earlier arc imported **194** reconstructions from another decompilation and
  re-verified them word for word; they were **removed in M369** because that project publishes no licence, so the
  claims remain as measured extents and the text does not. Read the **177** that are not copies as the measure of how
  much was really understood; the
  [extended page](docs/README-extended.md#1-what-the-numbers-mean-and-which-ones-to-trust) has the table.
- **What is left, in the order it is worth doing**: the duplicate-body census — **34 candidates in 17 complete
  two-copy groups**, every one of them the same body at the same address in the two enemy-slot overlay variants
  (`ovl_008900e`/`ovl_008e046`), 28 to 146 words — then the four non-C extent corrections, the five published
  allocation residues, and the remaining bytes, of which **440 B** is honestly unclassified.

## What is decoded

| format | state |
|---|---|
| script VM | 141 handlers, **18 distinct instruction lengths** (1–40 B), decoded from the handlers' own behaviour |
| sample codec | order-2 ADPCM with a **256**-byte shared codebook, with **217 944** of **217 944** groups structurally valid and **1 180** of **1 192** samples decoding to audio |
| voice codec | a second, unrelated codec inside the 588-record `MORT` bank — reimplemented and graded **sample for sample**, 13 clips / 634 blocks / 0 differing |
| textures (T64) | palette plus raw indices, no compression — verified on **65 of 65** tiles |
| room population | 256 table entries → 147 ids → 50 room scripts |
| file table | the whole file system: 8 091 entries, 4 852 zlib and **3 126 stored raw** |
| exception path | `break` → vector → dispatch loop `0x8000098c`, no `eret` and no EPC write: fatal by design |

The full format reference — containers, key spaces, directory records, the voice bank's 12-byte header, and the one
record the cartridge never labels — is
[§5 of the extended page](docs/README-extended.md#5-format-reference), with the measurement behind each claim in
[docs/format_notes.md](docs/format_notes.md) and the structures codified in
[include/re2_formats.h](include/re2_formats.h).

## The jargon, in one line each

| term | meaning here |
|---|---|
| **image** | one loadable block of the cartridge — `boot`, `stage2`, or one of 34 overlays; 36 in total |
| **byte-exact** | our C compiles to the *same bytes* as the game's own object code, not merely equivalent behaviour |
| **splat** | a splitter that proposes code/data boundaries; here it proposes and the census disposes |
| **Ghidra** | the decompiler that produces the starting pseudocode; every `FUN_…` body in `src/` comes from it |
| **REA** | the local tooling that drives Ghidra/rizin over these images and captures the results reproducibly |

## No cartridge data, no affiliation

The cartridge is **not in this repository and never will be** — not in the tree, not in any commit. `rom/`, `assets/`
and `build/` are gitignored; the only `.z64` here is an 8 KiB *synthetic* fixture that exists so the pipeline can run
without the game. You need your own legally dumped copy to run anything that reads the cartridge, and nothing extracted
from it — no textures, no audio, no video, no compressed members — is committed. Not affiliated with, endorsed by or
sponsored by Capcom or Nintendo; the licence section, with the `src/` carve-out and the third-party credit, is
[§11 of the extended page](docs/README-extended.md#11-legal-and-licence).

## Rebuild with your own dump

```sh
python3 tools/n64info.py rom/re2.z64                          # identify and normalise the dump
python3 tools/unpack_zlib.py rom/*.z64 --out assets/unpacked  # 4 761 members, ~11 s
python3 tools/build_images.py rom/*.z64                       # 36 ELFs into build/elfs/
python3 tools/export_src.py                                   # build/decomp → src/
sh tools/ci.sh                                                # the whole gate, with the cartridge
```

The decompilation step itself is Ghidra 12.2 driven through REA's CLI, one invocation per image, seeded from
`config/symbols.tsv` — hours, not minutes. The full sequence, including the fixture order that has bitten twice, is
[§8 of the extended page](docs/README-extended.md#8-rebuild-with-your-own-dump) and
[docs/handover.md](docs/handover.md).
